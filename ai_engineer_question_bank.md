## Section 1: Overview & Competency Framework

For an AI Engineer or Applied AI Engineer, the central architectural question is:  
**"Why does an AI project start with a 1,000-line deterministic Python parser instead of sending the entire raw screenplay to a frontier Large Language Model?"**

An interviewer will scrutinize your system design to determine whether:
1. You understand the **fundamental limits of LLMs** (inability to execute exact arithmetic, nondeterminism, token costs, hallucinated boundary citations).
2. You understand **Symbol Grounding**: how Phase 1's atomic AST IDs (`EP01_EL010`) act as immutable geometric anchors for all downstream generative reasoning (Batch Extractor, Cross-Episode Synthesis, Cold-First Critic).
3. You can design **hybrid architectures**: coupling rule-based deterministic compilers with generative models for semantic interpretation.
4. You know how to replace heuristic synthetic pacing (`len(words) * 30`) with modern multimodal models (Whisper speech-to-text forced alignment).

## Section 2: Complete Question Bank with Metadata & Defenses

### Domain 1: Architectural Division of Labor (Deterministic Code vs. LLMs)

#### Q-AI-01 [P0 | Advanced | Architecture & Defense | Reported Industry Question]
**Question:** In Phase 1, you built a custom deterministic parser (`UniversalScreenplayParser`) using regular expressions and state-machine logic. Why not simply prompt Google Gemini 2.5 Flash or GPT-4o with a Pydantic schema to parse the raw screenplay into an AST directly?
* **Why This Priority (P0):** The definitive question an AI hiring manager or CTO will ask. It separates engineers who understand production trade-offs from those who treat LLMs as universal hammers.
* **Evidence:** Standard interview prompt at AI-first startups (Sarvam AI, Krutrim, Postman, LeetCode Discuss).
* **Technical Defense / Expected Answer:**
  - *Sub-Second Arithmetic & Determinism:* LLMs are autoregressive next-token predictors. They perform arithmetic via probabilistic token transitions, not internal ALU computation. When calculating `duration_cs = end_cs - start_cs` or checking whether a clip satisfies $20.00\text{s} \le \text{dur} \le 60.00\text{s}$, LLMs frequently suffer off-by-one errors and floating-point drift. Code is $100\%$ mathematically deterministic.
  - *Cost & Token Efficiency:* Parsing 50 episodes (~6,000 lines, 150,000 tokens) via an LLM would consume hundreds of thousands of input and output tokens per run. The Python parser parses all 50 episodes in **$< 1.5$ seconds** at **\$0.00 API cost**.
  - *Hallucination Prevention:* LLMs can hallucinate missing dialogue lines, alter punctuation, or skip non-dialogue camera cues. A deterministic parser guarantees 100% text fidelity (verbatim character-for-character extraction).
  - *The Hybrid Paradigm:* Code does what code does best (lexical tokenization, integer arithmetic, schema validation); LLMs do what LLMs do best (narrative comprehension, dramatic irony, thematic synthesis).

#### Q-AI-02 [P0 | Advanced | Conceptual & Architecture | Project-Derived Prediction]
**Question:** Explain the concept of "Symbol Grounding" in your system. How does the AST generated by `ast_builder` prevent downstream Gemini models from hallucinating clip boundaries in Phase 3 and Phase 5?
* **Why This Priority (P0):** Directly connects Phase 1 output to Phase 3/4/5 prompt architecture and downstream reliability.
* **Evidence:** Core topic in AI safety, agentic workflow design, and enterprise LLM architecture.
* **Technical Defense / Expected Answer:**
  - *The Symbol Grounding Problem:* In classic AI, symbol grounding refers to how abstract symbols acquire semantic meaning tied to concrete physical realities. In LLM pipelines, it refers to binding generative outputs to immutable, verified source references.
  - *How Phase 1 Implements Grounding:* Every screenplay element is assigned an immutable alphanumeric ID: `EP{ep:02d}_EL{el:03d}` (e.g., `EP01_EL010`) alongside exact `start_cs` and `end_cs`.
  - *Downstream Enforcement:* When Gemini extracts candidate promo clips in Phase 3, the prompt forbids it from generating start/end timestamps. Instead, it must cite existing `start_element_id` and `end_element_id`.
  - *Mechanical Verification:* In Phase 5 (`validator_ranker.py`), the mechanical gate queries `01_structured_episodes.json` directly using the cited IDs to fetch exact timestamps. If an ID does not exist in the AST, the candidate is discarded immediately. The LLM cannot hallucinate timestamps because it is never allowed to generate them.

### Domain 2: Document Chunking, Context Design & Token Economics

#### Q-AI-03 [P0 | Intermediate | System Design | Reported Industry Question]
**Question:** How does the AST structure influence your document chunking strategy for downstream LLM prompts? Why is AST-aware semantic chunking superior to fixed-size sliding window chunking (e.g., 500-token chunks with 50-token overlap)?
* **Why This Priority (P0):** RAG and LLM context chunking is a universal interview evaluation topic across all Applied AI tracks.
* **Evidence:** Reported in Applied AI rounds at InMobi, Glance, and Global AI Labs.
* **Technical Defense / Expected Answer:**
  - *Failure of Fixed-Token Chunking:*
    1. **Boundary Splintering:** A fixed 500-token window can slice directly through the middle of a spoken sentence or separate a character cue (`**MATRIARCH:**`) from their dialogue (`"You should turn around"`).
    2. **Loss of Turn-Taking Structure:** Dialogue requires conversational context (who is answering whom). Naive chunking destroys conversational cohesion.
  - *AST-Aware Semantic Chunking:*
    Because Phase 1 builds a tree of `Episode -> Scene -> ScreenplayElement`, chunking can occur at natural dramatic boundaries:
    - *Scene-Level Chunking:* Every scene is a self-contained dramatic unit with heading, setting, and participants.
    - *Turn-Level Preservation:* Dialogue blocks and parenthetical delivery tones are never split.
    - *Context Window Packing:* In Phase 3, episodes are packed into 5 batches of 10 episodes (~20,000 tokens per batch), fully fitting within Gemini's 1M+ context window while maintaining pristine structural boundaries.

#### Q-AI-04 [P1 | Intermediate | Mathematical / Economics | Project-Derived Prediction]
**Question:** Calculate the token economics and latency implications of your AST representation. By pre-computing durations in Phase 1 and passing them directly to the LLM, how much token overhead and inference latency do you save?
* **Why This Priority (P1):** Tests production cost awareness and latency optimization skills.
* **Evidence:** Project documentation (Section 16: Cost & Scalability).
* **Technical Defense / Expected Answer:**
  - *Without Pre-computation:* If the LLM were required to calculate timings, each prompt would need to include raw start/end timestamps for every cue (`Start: (00:11.30) | End: (00:13.10)`), and the output prompt would require the LLM to generate start, end, and duration floats.
  - *Token Savings:* Formatting elements as compact dialogue lines with pre-calculated duration tags `[EL010 | 2.1s] GERALD: "I cannot wed..."` reduces token count by $\sim 35\%$ compared to raw screenplay blocks.
  - *Inference Latency:* Generating fewer output tokens directly reduces Time-To-Last-Token (TTLT), since autoregressive generation speed scales linearly with output tokens ($O(T_{\text{out}})$). Across 5 batches, output tokens are kept under 2,000 tokens per batch, completing inference in $\sim 12\text{s}$ per batch.

### Domain 3: NLP, Text Processing & Regex Tokenization

#### Q-AI-05 [P0 | Advanced | Implementation & NLP | Project-Derived Prediction]
**Question:** In `UniversalScreenplayParser.decompose_tag`, you use a rule-based parser to extract `speaker`, `modifier` (e.g. `'O.S.'`, `'V.O.'`), and `delivery` (e.g. `'Cold, Commanding'`). What are the edge cases where this heuristic fails, and how would you replace it with an NLP / Named Entity Recognition (NER) model?
* **Why This Priority (P0):** Directly inspects the regex/string decomposition logic in `parser.py#L293-L329` and tests modern NLP alternatives.
* **Evidence:** Project-derived code deep dive & common NLP engineering interview question.
* **Technical Defense / Expected Answer:**
  - *Current Heuristic Logic in `parser.py`:*
    ```python
    parens = re.findall(r"\((.*?)\)", tag)
    first_paren_idx = tag.find("(")
    speaker = tag[:first_paren_idx].strip() if first_paren_idx != -1 else tag.strip()
    ```
  - *Failure Edge Cases:*
    1. **Character Names with Parentheses/Titles:** e.g., `CAPTAIN (RETIRED) (SHOUTING):`. The parser extracts `speaker = "CAPTAIN"`, `modifier = "RETIRED"`, dropping the military title into the modifier slot.
    2. **Missing Parentheses for Delivery:** e.g., `MATRIARCH - COLDLY:`. The colon/dash delivery is missed; speaker becomes `"MATRIARCH - COLDLY"`.
    3. **Multiple Modifiers:** e.g., `JULIANA (O.S.) (WHISPERING) (TEARFULLY):`. Delivery concatenation `|` handles this, but modifier extraction only checks `parens[0]`.
  - *Modern NLP / NER Replacement:*
    - Train a fine-tuned token classifier (e.g., SpaCy or DistilBERT token classification) using BIO tagging:
      `B-SPEAKER`, `I-SPEAKER`, `B-MODIFIER`, `B-DELIVERY`, `I-DELIVERY`.
    - Train on 1,000 annotated screenplay tags. A lightweight DistilBERT model runs in $< 2\text{ms}$ on CPU and generalizes to arbitrary non-standard character headers without brittle regex rules.

#### Q-AI-06 [P1 | Advanced | Compiler & NLP | Common Industry Question]
**Question:** In `parser.py`, you used regular expressions (`re.compile`) to parse element blocks. Under what conditions does regular expression parsing break down for hierarchical text, and when must you upgrade to a Context-Free Grammar (CFG) or Recursive Descent Parser?
* **Why This Priority (P1):** Tests fundamental theoretical computer science and parsing theory (Chomsky Hierarchy).
* **Evidence:** Standard compiler design and NLP infrastructure interview topic.
* **Technical Defense / Expected Answer:**
  - *Chomsky Hierarchy Limits:* Regular expressions correspond to **Type-3 Regular Grammars** (finite-state automata). They cannot parse arbitrary nested or recursive structures (e.g. nested parentheticals like `((A and B) or C)`) because finite automata lack a memory stack.
  - *When Screenplay Regex Breaks:*
    1. **Arbitrarily Nested Parentheticals:** Actors speaking dialogue with nested parenthetical actions: `"Wait (she hesitates (glancing back)) don't go!"`.
    2. **Multi-level Indentation / Blocks:** Screenplays with nested voiceover asides or dual dialogue (two characters speaking simultaneously in two vertical columns).
  - *When to Upgrade to CFG / Recursive Descent:*
    When parsing multi-column Hollywood dual dialogue or scripts with recursive stage directions, you must use a **Context-Free Grammar (Type-2)** parsed via a Lexer + Parser pipeline (e.g., ANTLR, Lark, or a custom Recursive Descent Parser with a token stack).

### Domain 4: Multimodal AI & Pacing Alignment (Whisper vs. Heuristics)

#### Q-AI-07 [P0 | Advanced | Applied AI & Multimodal | Project-Derived Prediction]
**Question:** In `_parse_standard_screenplay` (for scripts without timestamps like The Dark Knight), you use a heuristic pacing formula: `dur_cs = max(100, len(words) * 30)` (~0.3s per word). Why is this heuristic insufficient for production video editing, and how would you build a multimodal AI pipeline using Whisper to achieve exact syllable-level alignment?
* **Why This Priority (P0):** Core vulnerability identified in project documentation (Section 14 & 18.3).
* **Evidence:** Direct match for production speech tech at Kuku FM and Pocket FM.
* **Technical Defense / Expected Answer:**
  - *Why the Heuristic Fails:*
    - Pacing variance: A tense pause ("...") takes 3 seconds for 0 words; rapid auctioneer dialogue takes 0.15s per word.
    - Emotional pauses, music risers, and action choreography take screen time completely decoupled from word count.
  - *Multimodal Forced Alignment Architecture:*
    ```mermaid
    flowchart LR
        A["Screenplay Text (AST)"] --> C["Forced Alignment Engine<br>(WhisperX / CTC)"]
        B["Episode Audio (WAV)"] --> C
        C --> D["Exact Syllable Timestamps<br>start_cs, end_cs"]
        D --> E["Updated AST Elements<br>Zero Timing Drift"]
    ```
    1. **Audio Ingestion:** Ingest the recorded episode audio track (`WAV` at 16kHz).
    2. **Acoustic Phoneme Modeling:** Use **WhisperX** or a Connectionist Temporal Classification (CTC) alignment model (such as `wav2vec2-alignment`).
    3. **Dynamic Time Warping (DTW):** Align known AST dialogue text against the speech phonemes to produce exact word-level and syllable-level timestamps down to $\pm 10\text{ms}$.
    4. **AST Backfill:** Update the AST's `start_cs` and `end_cs` with empirical acoustic timestamps, replacing synthetic heuristics with ground-truth audio timing.

### Domain 5: AI System Reliability, Fallbacks & Error Recovery

#### Q-AI-08 [P1 | Intermediate | Reliability | Reported Industry Question]
**Question:** If you deployed an ML-based screenplay parser (e.g., an LLM or sequence tagger) in production, how would you design a hybrid fallback architecture so that an ML failure never halts the data ingestion pipeline?
* **Why This Priority (P1):** Tests production-grade fault tolerance, graceful degradation, and system resilience.
* **Evidence:** Standard architectural question at high-throughput startups (Swiggy, Meesho, ShareChat).
* **Technical Defense / Expected Answer:**
  - *Primary-Secondary Fallback Cascade:*
    1. **Tier 1 (Fast Deterministic Parser):** Try regex-based `UniversalScreenplayParser`. It runs in 30ms. If `ValidationAudit.is_valid == True` and zero timestamp errors occur, accept the AST immediately.
    2. **Tier 2 (ML/LLM Assisted Parser):** If Tier 1 throws an error or detects $>15\%$ dropped lines (unparsed text), route the failed episode to a structured LLM parser (`gemini-3.8-flash` with Pydantic schema).
    3. **Tier 3 (Heuristic Line Chunking Fallback):** If the LLM API is unreachable or rate-limited (HTTP 429), fall back to raw newline-delimited sentence chunking with synthetic pacing, flagging the episode as `NEEDS_HUMAN_QA`.
  - *Telemetry & Circuit Breakers:* Use Prometheus metrics to monitor the fallback rate. If Tier 2 activations exceed $5\%$ of daily volume, trigger an engineering incident for screenplay template drift.

### Chain AI-1: The "Why Not LLMs?" System Design Defense

```
[Step 1: Conceptual] ──► What are the theoretical limitations of LLMs for parsing?
        │
[Step 2: Implementation] ─► How did you structure your regex parser to avoid hallucinations?
        │
[Step 3: Design Reasoning] ─► Why is deterministic symbol grounding necessary for downstream AI?
        │
[Step 4: Trade-off] ────► Latency, API costs, and rate-limits: Python vs. Gemini 2.5 Flash.
        │
[Step 5: Edge Cases] ───► What happens when screenplay text is malformed or unformatted?
        │
[Step 6: Optimization] ─► Hybrid approach: When should an LLM assist the parser?
```

1. **Interviewer:** *"Large Language Models can parse text, translate languages, and write code. Why did you write a custom Python parser instead of asking an LLM to output structured JSON?"*
   - **Candidate:** *"LLMs are probabilistic, autoregressive sequence models. They excel at semantic reasoning, style transfer, and thematic interpretation, but they are fundamentally unsuited for deterministic tasks requiring exact sub-second timestamp arithmetic, zero character loss, and strict invariant enforcement. Using an LLM to parse screenplay tags introduces non-deterministic hallucinations, adds massive API latency, and wastes compute budget on a task that deterministic finite automata solve in milliseconds."*
2. **Interviewer:** *"Show me where in your code you guarantee that zero text is lost or altered."*
   - **Candidate:** *"In `_parse_microdrama_screenplay`, lines 398–417 extract `content = em.group('content').strip()` directly from the regex match slice without any string rewriting or summarization. The exact text is placed directly into `ScreenplayElement(content=content)`. In traditional Hollywood parsing, line 829 flushes any unmatched lines into `accumulated_action` and emits them as `ElementType.ACTION`, ensuring no line of script text is discarded."*
3. **Interviewer:** *"You mentioned 'symbol grounding'. Why can't Gemini 2.5 Flash just read the raw text in Phase 3 and return timestamp intervals directly?"*
   - **Candidate:** *"Because if Gemini returns a start timestamp of `00:14.30` and an end timestamp of `00:35.30`, that timestamp is a hallucinated string. If the LLM shifts the boundary by 2 seconds, it might cut off the cliffhanger dialogue or clip into the next scene. By forcing the LLM to cite atomic AST element IDs (`start_element_id: 'EP01_EL010'`, `end_element_id: 'EP01_EL022'`), we ground the LLM's dramatic choices in immutable data. The duration is then computed deterministically in Python using verified AST integer centiseconds."*
4. **Interviewer:** *"What is the exact financial and latency cost difference between your approach and an all-LLM approach?"*
   - **Candidate:** *"Our 50-episode season contains 3,727 elements and ~150,000 tokens of raw text. Parsing this via an LLM with structured output would require ~150,000 input tokens and ~100,000 output tokens. At Gemini 2.5 Flash commercial rates, parsing alone would cost ~\$0.05 per run and take 60–90 seconds due to API roundtrips and rate limits. Our Python parser parses all 50 episodes in 1.4 seconds locally at \$0.00 cost, consuming 0 API quota."*
5. **Interviewer:** *"What happens when an author writes a script with typos, like missing asterisks (`CAMERA: Start: 00:00.00`)?"*
   - **Candidate:** *"In `UniversalScreenplayParser.parse_screenplay_file`, line 343 executes `self.element_pattern.search(text)`. If the script lacks the microdrama tag structure, it automatically falls back to `_parse_standard_screenplay`, which uses indentation profiling, slugline recognition, and transition keywords. If an individual line inside a microdrama script is malformed, it is currently absorbed into the preceding element's content. To improve this, we can add a fuzzy delimiter fallback."*
6. **Interviewer:** *"If you were to introduce an LLM into Phase 1, what specific task would you give it?"*
   - **Candidate:** *"I would use a small, fast model (like Gemini Flash or a fine-tuned 1B parameter SLM) strictly as an **Out-of-Distribution Error Recovery Agent**. When the deterministic parser flags an element as unparseable or detects a non-monotonic timestamp error during `ValidationAudit`, only that isolated 5-line snippet would be dispatched to the SLM to reformat into canonical tag syntax."*
7. **Interviewer:** *"How would you architect this into a self-healing production ingestion pipeline?"*
   - **Candidate:** *"I would implement a three-stage pipeline: (1) Deterministic regex parser executes; (2) `ValidationAudit` checks for anomalies; (3) Any failed files are routed to an LLM-assisted repair loop with a strict Pydantic contract; (4) Successful repairs are logged to a golden dataset used to continuously update the deterministic regex library, reducing LLM repair calls over time."*

### Chain AI-2: Multimodal Grounding & Speech Alignment

```
[Step 1: Conceptual] ──► What is the difference between screenplay text and filmed video?
        │
[Step 2: Implementation] ─► How did you handle timing for un-timestamped Hollywood scripts?
        │
[Step 3: Design Reasoning] ─► Why character-count interpolation fails in media tech.
        │
[Step 4: Trade-off] ────► Heuristic word-based timing vs. Whisper acoustic forced alignment.
        │
[Step 5: Edge Cases] ───► Handling actor ad-libs, stuttering, and unscripted pauses.
        │
[Step 6: Optimization] ─► Running forced alignment efficiently at scale (batch inference).
        │
[Step 7: Production] ───► Generating Final Cut Pro XML / DaVinci Resolve EDLs automatically.
```

1. **Interviewer:** *"Your project documentation repeatedly highlights that screenplays are text, not video. Why is that distinction critical for an AI Engineer working in content tech?"*
   - **Candidate:** *"A screenplay is a blueprint, not the finished media asset. A writer writes: `'Juliana turns, devastated.'` In text, that is 3 words (~0.9 seconds of reading time). On camera, the director might hold that close-up for 6.5 seconds with intense orchestral strings. An AI model optimizing for a 3-second hook cannot know whether that visual moment happens at second 1.0 or second 5.0 without multimodal alignment to the recorded audio/video waveform."*
2. **Interviewer:** *"How did you estimate element durations in `parser.py` when parsing Hollywood scripts like The Dark Knight?"*
   - **Candidate:** *"In `_parse_standard_screenplay`, line 722 implements a classic Hollywood script-timing heuristic: `dur_cs = max(100, len(words) * 30)`. This assumes an average speaking pace of ~200 words per minute (30 centiseconds or 0.3 seconds per word), with a 1-second floor (`100cs`) for single-word exclamations or short sound cues."*
3. **Interviewer:** *"Why did you explicitly forbid character-count interpolation in Phase 5?"*
   - **Candidate:** *"Character interpolation assumes that spoken duration is strictly proportional to character length ($T = k \times \text{chars}$). This fails catastrophically in dialogue: short words can be shouted or drawn out over seconds (`'NOOOOO!'`), while long sentences can be spoken rapidly. Pining cuts to character offsets leads to clipped syllables. Instead, we emit `verbatim_trim_quote` to instruct human editors to cut at natural audio pauses."*
4. **Interviewer:** *"How would you replace the synthetic heuristic with Whisper forced alignment?"*
   - **Candidate:** *"I would use WhisperX. We pass the episode audio and the AST dialogue text to a CTC forced alignment model. The acoustic model aligns the phoneme probabilities to the known screenplay text, emitting precise start and end millisecond timestamps for every individual word. We then update `ScreenplayElement.start_cs` and `end_cs` with true acoustic boundaries."*
5. **Interviewer:** *"What happens during forced alignment if the actor ad-libs a line or drops a sentence from the screenplay?"*
   - **Candidate:** *"Standard CTC alignment degrades or desynchronizes when text deviates from audio. To handle this, we compute an alignment confidence score per token. When confidence falls below 0.6 (indicating unscripted dialogue or ad-lib), we use Whisper's autoregressive speech-to-text to transcribe the audio segment, diff the transcription against the screenplay using Levenshtein distance, and patch the AST with the verbatim spoken words."*
6. **Interviewer:** *"Whisper alignment on 50 episodes of video could take hours. How would you optimize the inference pipeline?"*
   - **Candidate:** *"First, extract only the 16kHz mono audio stream using `ffmpeg`, discarding the video stream. Second, run batched Voice Activity Detection (VAD) using Silero VAD to strip silent sections before alignment. Third, utilize a quantized acoustic model (CTranslate2 / WhisperX) on GPU with batch sizes of 16. This processes a 2-minute episode in under 3 seconds."*
7. **Interviewer:** *"Once you have exact multimodal timestamps, how does your system hand off the promotional blueprint to human editors in Premiere Pro or DaVinci Resolve?"*
   - **Candidate:** *"We convert `final_promos.json` into an industry-standard Edit Decision List (EDL) or Final Cut Pro XML (FCPXML). An EDL file specifies source media reel names, track IDs, and exact timecode in-points and out-points (`01:00:14:09  01:00:35:07`). The video editor imports the XML into Premiere Pro, and the entire promotional cut appears on their timeline instantly, pre-trimmed to the exact frame."*
